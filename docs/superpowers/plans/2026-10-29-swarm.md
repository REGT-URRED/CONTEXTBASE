# ContextBase Swarm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real per-project agent swarm: one worktree and one session per worker, terminal opened, session ids handed to the orchestrator, worker state derived from files and git.

**Architecture:** Pure core in `src/swarm.js` with injected `exec`/`spawn` so tests never touch git or open windows. `src/swarm-agents.js` holds the per-CLI contract, session minting and launcher text. CLI and MCP are thin surfaces.

**Tech Stack:** Node >=18, ESM, zero dependencies, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-29-swarm-design.md`

## Global Constraints

- Zero runtime dependencies, ESM, Node >= 18.
- No breaking changes to existing commands/exports (61 tests pass today).
- User text never enters a command line; it lives in `task.md`.
- `--auto` never passed by default.
- Non-opencode agents return `supported: false` with a reason; never faked.
- Records updated in Spanish at the end. Commit author `REGT-URRED <U19211826@utp.edu.pe>`, no AI attribution.

## Review Focus

- Silent worker must report `stale` with evidence, never `running` forever.
- Task text with quotes/newlines/`%` must not break the launcher.
- Half-failed `start` must not leave a state file claiming a spawn that never happened.
- Session id rejected by the CLI: surface the CLI error, do not retry with a new id.
- `stop` on an already-dead pid must not throw.
